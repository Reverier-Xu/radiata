## 0. 服务愿景下的设计目标

radiata 的愿景：任何网络环境（同机回环、局域网、跨域 WAN、间歇弱网）里，一个去
中心化集群的成员在**一次凭证合并后**，身份、信任、成员与资源元数据自动确定性收敛，
应用层数据面自由路由。同步平面因此要满足：

| 目标 | 度量 |
| --- | --- |
| G1 载荷零重复 | 稳态单行变更：行字节投递次数 / 必要次数 → 1×（现状 ≈ k×） |
| G2 冗余随链路伸缩 | 强连通：摘要流量也趋近于单次；弱网：冗余只加在摘要/重试上，载荷仍 1× |
| G3 确定性不变 | 相同行集合 + 相同消息集合 ⇒ 相同收敛结果；fuzz/golden vector 契约原样保留 |
| G4 有界不变 | 每消息、每会话在飞、每 tick 工作量全部有上界 |
| G5 延迟不退化 | 强网下单行变更的端到端收敛延迟 ≤ 现状（1 tick/跳）；弱网不劣于现状重发 |

## 1. 终态架构总览

```
┌──────────────────────────────────────────────────────────────┐
│                        存储（journal + snapshot）             │
│   每泳道一棵「指纹索引」：按行哈希序的有序结构，               │
│   结点聚合 (count, xor64(row_hash))，插入/删除 O(log N)       │
└───────────────▲──────────────────────────────▲───────────────┘
                │ 读/写行                        │ 区间指纹查询
┌───────────────┴──────────────────────────────┴───────────────┐
│                     和解引擎（每会话·每泳道一实例）           │
│   ROOT/HINT/OFFER/NEED/ROWS 状态机 + 有界在飞窗口             │
│   幂等 apply（复用现有各泳道 merge 语义）                     │
└───────────────▲──────────────────────────────▲───────────────┘
                │ eager-delta（强网抢跑，有界）  │ 摘要 hint
┌───────────────┴──────────────────────────────┴───────────────┐
│        会话层（TLS1.3 认证流、admission-ack truth）【不动】   │
├──────────────────────────────────────────────────────────────┤
│  连接平面：k(n) 度维护 / 恢复拨号 【不动，与同步平面正交】     │
└──────────────────────────────────────────────────────────────┘
```

三个明确分层：

1. **载荷层**：行字节只在两种情形出现 —— 对端 `NEED` 证明缺失后的应答，或
   eager-delta 首跳的顺手携带（有界小 delta，幂等去重）。此外**任何**路径都不再
   携带行字节。
2. **摘要层**：区间指纹（(count, XOR) 对）与变更 hint。可重复、可丢失、可乱序，
   代价是几十字节级，这是唯一的「冗余预算」支出点。
3. **传输层**：现有认证会话与投递真相纪律，一字不改。

## 2. 核心数据结构：指纹索引（每泳道一棵）

- **有序性按行哈希而非业务键**：元素序 = `row_hash`（64/128 位内容哈希）的字典序。
  好处：键空间倾斜（成员 ID 前缀聚集、资源命名空间聚集）不会造成区间切分失衡 ——
  内容哈希天然均匀。
- 结点聚合值 `agg = (count, xor)`，`xor` 为子树内所有 `item_hash` 的 XOR
  （`item_hash ≠ row_hash`：前者对「键+行内容」再哈希一次，避免同内容不同键的抵消
  病理）。空区间 `agg = (0, 0)`。
  - 联检 `count` 与 `xor`：纯 XOR 碰撞（不同集合同 XOR）需要计数也相同，工程上
    视为不可能（N ≤ 2^20 量级下碰撞概率 << 2^-60）。
  - XOR 群运算可交换、可消去 ⇒ 任意区间指纹 = 两个前缀指纹之差，路径查询 O(log N)。
- 实现载体：现有有序存储快照（`store.snapshot()` 的 keyset 扫描）之上建一层内存
  聚合索引（B 树或跳表）。行写入 → O(log N) 更新聚合；断言：索引是**存储的派生
  视图**，进程重启从快照重建，不落盘、不需要过期重建（对比 Riak AAE 临时树与
  watermark 表：漂移病根除 —— `01` 根因 ①）。
- 每泳道键空间：
  - `descriptors`：元素 = 成员描述符行；
  - `trust`：元素 = 签发者快照分页；
  - `resources`：元素 = 资源行（键+版本+内容哈希）；
  - `tombstones`：leave/cleanup/revocation/checkpoint 行（与现状同集合语义，
    GC 仍由 cleanup checkpoint watermark 驱动 —— 检查点机制不动）。

## 3. wire 契约（新泳道协议，冻结后 golden vector 钉死）

在现有会话多路复用上注册一个新协议标签（如 `radiata…/protocols/reconcile-v1`），
消息体 CBOR canonical 编码，全部有界：

| 消息 | 方向 | 载荷 | 语义 |
| --- | --- | --- | --- |
| `ROOT` | 双向 | `{lane, count, xor}` | 我当前整泳道摘要。会话建立时、检测节拍时、协商完成后发送 |
| `HINT` | 双向 | `ranges[]`（每项 `{bound, count, xor}`，≤32 项） | 尽力而为的变更通知：「这些区间变了」。可丢、可重、可忽略 |
| `OFFER` | 双向 | `ranges[]`（有界） | 我对这些区间的摘要（应答 ROOT/HINT 或协商中递归二分） |
| `NEED` | 双向 | `bounds[]`（有界） | 我缺这些区间的行，请给 |
| `ROWS` | 双向 | `rows[]`（复用现有分页行编码与 32/64 KiB 分块纪律） | 行载荷，幂等 apply |
| `DONE` | 双向 | `{round_token}` | 一轮协商的窗口对账（背压用，可选捎带在最后一条 OFFER） |

协商算法（确定性，`05` §3.1 的 RBSR）：

```text
对每个收到的区间摘要 r：
  local = 本地同区间聚合
  if local == r:            无事可做（区间和解完成）
  elif r.count == 0:        NEED r            # 对端空，我全有
  elif local.count == 0:    NEED r（对端全给我）
  else:                     OFFER [left(r), right(r)]   # 二分递归，可多分
```

- **多分因子 b**：wire 上 `OFFER` 一次可带 b 个子区间（默认 b=4），轮次从 log₂
  降为 log_b，回环低 RTT 场景收敛更快；b 是常量，不是协商参数。
- **流水线化**：每会话每泳道最多 1 个在飞协商 + 有界 ROWS 窗口（复用现有
  admission-ack delivery truth 与 chunk 泵），协商与传输交错进行，不锁步。
- **多跳传播**：节点应用行后指纹索引更新 → 对自己的其它对端发 `HINT`（变更区间
  +新摘要，几十字节）。流行病波**只传播摘要**；对端发现摘要不等才发起协商 ——
  载荷仍只在「证明缺失」的边上走一次。`01` 根因 ② 就此消除。

## 4. 触发与调度（替代反熵 tick 的节拍体系）

| 触发源 | 行为 |
| --- | --- |
| 本地行写入 | O(log N) 更新索引；对全部已连接对端发 `HINT`（合并去抖：每 tick 汇总一次，抖动上限 = 现有 `anti_entropy_interval`） |
| 收到 `HINT` | 与本地索引比对：全部相等 → 静默（强网稳态的常态，零往返）；不等 → 发起协商 |
| 会话建立 | 互发 `ROOT`；不等 → 全量协商（新对端/重连对端的第一桶） |
| 检测节拍（静默兜底） | 每 `DETECTION_CADENCE_TICKS`（32 tick ≈ 32 s）对轮换窗口内的对端互发 `ROOT`：成本 O(1) 字节 × 每对端 1/32s，替代现状的全目录扫描 |
| 协商中 | 在飞窗口纪律，完成即 `DONE`；丢消息由检测节拍与下一次变更自愈 |
| eager-delta（抢跑） | 变更写入时，若该泳道变更行编码 ≤ 阈值（如 4 KiB）且会话链路健康，`HINT` 直接捎带行本身；接收方幂等 apply 后索引更新，通常使协商完全不再发生 |

**删除的周期性成本**：watermark 表清空全量重发（64 pass）、静默目录扫描
（256 行/tick/对端）、墓碑 8-tick 重发与确认重查。静默期的全部成本收敛为每对端
每 32 s 一个 ~40 字节 `ROOT`。

## 5. 网络自适应（用户痛点的正面回应）

每会话维护轻量链路画像：EWMA(RTT)、未决超时率、协商重试率。画像只控制两个旋钮：

| 旋钮 | 强连通（回环/LAN） | 弱网（WAN/移动） |
| --- | --- | --- |
| `HINT` 重复度 | 1 次，不重发 | 未确认则按退避重发（摘要幂等，重发无害且便宜） |
| eager-delta | 开启（阈值可放大） | 关闭或收紧（丢一个 delta 浪费 4 KiB，不如等协商） |
| 检测节拍 | 基础 32 tick | 自动加密（如 ×¼），收敛更快 |
| 载荷路径 | **恒为 NEED 驱动或单次首跳** | 同左 —— **载荷永不因弱网而复制**，弱网的代价是重试（幂等）带来的延迟，不是冗余 |

要点：自适应只作用于**摘要与提示的冗余预算**（G2），载荷的零重复是**结构不变量**
而非调参结果。这是与现状的本质区别：现状把弱网保险费按固定比例（≈k×）强加给
所有网络环境。

## 6. 安全与有界性（不变量清单）

- I1 行信任仍完全来自认证会话 + 行自身签名（C4 不变）；指纹与摘要是**路由提示**，
  不承担完整性责任 —— 恶意摘要最多造成多余协商或多余传输，被接收方索引幂等吸收，
  无法造成状态污染。
- I2 所有消息有界：`ranges[]` ≤ 32 项/消息、`ROWS` 复用 256 KiB/4 096 chunk 的
  drain 纪律与 32/64 KiB 泵分块（C3 原样）。
- I3 每会话每泳道在飞协商 ≤ 1，ROWS 窗口有界 → 恶意对端的资源消耗上限不高于现状。
- I4 解码 canonical、fail-closed；未知 lane/消息类型拒收并按现有会话纪律处置。
- I5 确定性：协商输出只依赖两侧集合内容与消息集合（集合语义 + 交换群指纹），
  与到达顺序无关（C1）—— 仿真器与 fuzz harness 原样可用。
- I6 隐私：摘要泄露的信息量为区间计数 + 哈希异或，不泄露行内容；行本就不加密
  （集群内明文 + 签名），无回归。

**删除**：
- `WatermarkWalk` 状态机及全部 per-peer watermark 表、refresh pass、扫描游标、

- 反熵 tick 的全对端轮转调度（`SYNC_PEERS_PER_ROUND` 窗口）—— 协商按需触发，
  轮转只保留给检测节拍的 ROOT 交换；
- 三泳道各自的 push 引擎重复实现（~2 500 + ~1 100 行的两个 sync 模块收敛为单一
  和解引擎 + 泳道参数）。

**保留（经论证的既有资产）**：
- 会话层、传输层、admission-ack delivery truth、分块泵与有界纪律；
- 各泳道的**合并语义**（owner-marked / 单调并集 / LWW+CAS / 终态墓碑）与
  cleanup checkpoint GC；
- 连接平面：k(n) 度维护、恢复拨号、typed member-dial（与本方案正交）；
- 存储层：journal + snapshot + epoch 通知（epoch 变更 → 触发 HINT，语义同现状

- 仿真/混沌/契约测试基建 —— 它们是本方案验收（§9）的载具。

## 8. 复杂度与内存账

| 项 | 现状 | 终态 |
| --- | --- | --- |
| 稳态单行变更载荷投递 | ≈ n·k 次 | ≈ n−1 次（每缺行节点恰一次） |
| 稳态单行变更摘要流量 | —（无摘要层） | O(changes × degree) × ~40 B |
| 静默期每对端成本 | 32 tick 一轮全目录扫描 + 64 pass 一次全量重发 | 每 32 tick 一个 ROOT（~40 B） |
| 同步相关内存 | O(N × peers)（watermark 表，8 192 行/对端上限） | O(N)（每泳道一棵索引） |
| 本地写入成本 | 写行 + epoch | 写行 + O(log N) 索引更新 |
| 新对端全量同步 | 全目录分页推送（受 cadence 与窗口限制） | log 轮摘要协商 + 必要行（差异小时远快于现状） |

## 9. 验收 gate 与阶段计划

**Gate（进入 backlog 时逐项挂接）**：
- V1 `verify-sync-budget`（新增 lane）：simulation 注入稳态变更矩阵（n ∈ {8,64,256}
  × 单行/批量/离线重连），断言载荷投递冗余 ≤ 1.05×、强网摘要流量 ≤ O(changes×k×40B)
  实测阈值、弱网（20% 丢包注入）收敛时间不劣于现状模型；
- V2 既有收敛/崩溃/混沌 lane 全绿（membership、trust、resource、tombstone 四泳道
  的确定性收敛不变）；
- V3 canonical wire golden vector + fuzz corpora 覆盖全部新消息类型（含恶意有界
  构造）；
- V4 静默 mesh 24 h 仿真：每节点摘要流量上限断言（无全量重发事件）。

**阶段（每阶段独立可合并、可验证）**：
1. **指纹索引原语**：聚合有序结构 + 区间查询 + 属性测试（结合律/消去律/重启重建
   等价）。纯库内模块，无 wire。
2. **和解引擎与 wire v1**：状态机 + 消息编解码 + golden vectors；用内存对（进程内
   双实例）驱动收敛属性测试。
3. **泳道迁移**：四泳道全部改由和解引擎承载；删除 WatermarkWalk 与 push 引擎；
   既有泳道契约测试作为等价性验收。
4. **触发与自适应层**：HINT 去抖、检测节拍、eager-delta、链路画像与旋钮；
   V1/V4 lane 上线。
5. **文档与清理**：`radiata::guide` 重写同步章节；backlog 结项归档。

## 10. 风险与开放问题

| 风险 | 缓解 |
| --- | --- |
| 指纹碰撞 | 64 位 item_hash + count 联检；碰撞概率在目录 ≤ 2^20 下 << 2^-60；wire 预留 128 位升级位（指纹宽度是行格式常量，冻结前定案） |
| 多 RTT 协商延迟（深差异、大目录） | 多分因子 b=4；eager-delta 首跳；差异 O(N) 时本来需要 O(N) 字节，RBSR 最坏情形即信息论下界 |
| `HINT` 风暴（高频写放大） | 每 tick 汇总去抖（复用 interval 作为上限）；区间合并 |
| 恶意对端以垃圾 OFFER 逼计算 | I2/I3 有界 + 会话终止纪律既有 |
| 索引内存（超大目录） | O(N) 结点、每结点 ~40 B；与现状 watermark 相比是净减；必要时聚合层可懒构建（本周期不做） |
| 检测节拍期间静默漂移（收不到任何消息） | ROOT 交换 O(1) 便宜，可较现状更频繁；且任何本地变更与 HINT 都会顺带修复 |
| 开放问题 | eager-delta 字节阈值的最优值（阶段 4 用 V1 lane 标定）；四泳道是否合并为单流复用以省会话数（wire 冻结前决定）；检测节拍的自适应倍率曲线 |

## 11. 术语表

- **指纹（fingerprint）**：区间内所有 `item_hash` 的 XOR 与计数组成的聚合对。
- **和解（reconciliation）**：双方通过区间摘要比对得出对称差并只传缺失行的过程。
- **hint**：尽力而为的变更摘要通知，可丢可重。
- **eager-delta**：变更时随 hint 顺带捎带的有界行载荷（push 头，pull 尾中的 push）。
- **泳道（lane）**：一个独立收敛键空间（descriptors/trust/resources/tombstones）。
