# 客户集成摩擦点记录（9 实例集群 example）

> 以"不了解 radiata 内部实现的客户"视角，用纯公共 API 搭建 9 实例集群 +
> HTTP resource getter/setter 的全过程记录。凡必须绕过/深入内部才能完成
> 的事项均入档评估。

## 发现清单

| # | 摩擦点 | 严重度 | 状态 |
| --- | --- | --- | --- |
| 1 | **没有生产级 KeyProvider**：客户必须自行实现带崩溃恢复语义的密钥生命周期（`create_ed25519`/`reconcile_create`/`delete`/`reconcile_delete`，`KeyCreateState::{Present,Absent,Unknown}` 三态）。库内只有测试用的 ScriptedKeys。实现一个幂等的文件版 provider 是接入中最难的一步，且做错恢复语义的后果（身份丢失/重复）不易察觉。 | 高 | 已在 example 中提供 FileKeyProvider 参考实现；建议库内提供生产参考实现或深入文档 |
| 2 | **凭据轮换使已发凭据立即失效，且无只读查询当前凭据的 API**：`RotateMergeCredential` 是唯一的凭据签发口。多个节点并发自举时互相轮换、互相作废，join 永远失败；客户必须串行化 join 或带外分发同一个 token。 | 高 | example 采用编排器串行 join；建议提供"签发不轮换"的查询或多次有效的凭据选项 |
| 3 | **监听器服务过期 join hint（库缺陷，本战役已修）**：accept 循环在阻塞等待连接前计算 hint 快照，期间凭据轮换不被反映；joiner 校验 hint 与凭据世代不一致即拒。症状：轮换后第一次 join 必败，且"每次重试重新取 token"会让失败永久化。修复：hint 改为每连接在 TCP accept 后、写升级响应前评估（`TransportListener::accept` 收 hint 回调，crate 内部 trait，不涉公开 API）。 | 高（已修） | commit 本次 |
| 4 | **重启实例不自动回连**：持久化存储里有全部成员描述符与信任绑定，但恢复控制器只处理“有会话节点间的分区”——零会话的孤立重启节点不会拨号已知成员，必须操作员再次 `POST /join`。 | 中（已修） | 已修：recovery 首个 tick 从持久化证据（信任绑定后的已发布描述符，排除自身/removed/left/cleaned/主动断开）一次性补水 known-online 集，重启节点无操作员干预被动回连；json/redb 重启集成测试钉住 |
| 5 | **json 存储适配器为 test-only**：默认 feature 是 json，但生产路径必须启用 redb feature 并用 `adapters::redb_store`。默认 feature 与生产推荐的错位容易踩坑。 | 低 | 文档已明确；建议反转默认 feature 或在文档头部加粗提示 |
| 6 | **资源名是域限定标签语法**：`ResourceName` 形如 `demo.org/resources/kv1`（域/类别/名），简单键值用户会尝试 `kv1` 被拒。 | 低 | 设计使然（全局命名空间防冲突）；可在文档给常见名字模板 |
| 7 | **无环境/配置辅助**：端点构建、数据目录、peer 列表全靠客户代码。 | 低 | 库的合理边界；列出仅为完整 |
| 8 | **`DisconnectPeer` 拆会话不分"谁拨的"**：交叉拨号收敛为单一会话后，任一侧 disconnect 都会拆除整条会话——编排器拆自举星腿时必须小心不要拆掉成型图的边。 | 低 | 行为合理；编排脚本已按成型图保留边 |
| 9 | **离开的身份永远留在成员页**：`PageMembers` 不过滤 left 身份，成员计数含死记录，且无公开 API 能区分哪个成员已离开——客户无法从公共面计算“存活成员数”。生命周期实测：leave 后 members 仍为 10（9 活 + 1 左）。 | 中（已修） | 已修：`MemberView::status()` 返回 `MemberStatus::{Active,Left,Cleaned}`，观测层从 leave/cleanup 终局记录标注；成员页保留描述符（证据语义）但状态不再是活跃 |
| 10 | **同步游标跳过连接空窗期的写入（P1）**：资源/描述符反熵的 per-peer keyset 游标在会话死亡后仍保留，重连后的新会话从旧游标继续——网络分区/重挂期间写入的数据对游标已越过的对端永不重传。生命周期实测：分区写入 split-b 在治愈后 182s+ 仍停留在写入者本地，冲突寄存器两侧各自持不同胜者无法归一（6:1:2 分布）。 | 高（已修） | 已修：资源与成员反熵均改为每对端游标，会话死亡即清除状态，重归对端首轮全量补发（含周期性全扫兑底）；成员侧的首次落地曾引入 cleanup 墓碑传播回归，根因（发射页指纹未记录导致重发节奏锈死）已修复并重新合入 |
| 11 | **恢复控制器永不遗忘离开身份（P1）**：`recovery_history` 只增不删，left/cleaned 成员永远计入 pending → 控制器永不 quiesce、`attempts` 无限增长 → 退避钉死在最大值（默认 300s）→ 后续任何分区/断链的重新拨号节奏慢到不可用。生命周期实测：E7 分区后 B 侧内部网格 45s 内无法重建、E8 治愈 180s 窗口内冲突寄存器 6:1:2 无法归一。 | 高（已修） | 已修：recovery tick 剪除 left/cleaned 身份；新增 `GetRecovery` 查询（事件文档本就承诺 pull 视图）；集成测试钉住“离开后控制器必须归零 pending” |
| 12 | **命名监听端点绑死启动时 IP（P1）**：`TcpListener::bind((host, port))` 把通告名字（如 `wss://n5:9443`）解析成一次性 IP 后绑死。任何网络迁移（容器换网、DHCP 换址）后监听器成孤儿——入站拨号全部失败，出站拨号正常，节点呈现“半离奇”状态。生命周期实测：E7 分区后 B 侧五个成员的 9443 监听全部失效，互拨全 Io 失败，内部网格永远无法重建；治愈后 n6/n7/n8 会话数为 0。 | 高（已修） | 已修：字面 IP 按原样精确绑定；DNS 名字绑定所解析族的通配地址（名字是通告语义，不约束套接字）；发布端点保留原 host + 实际绑定端口（`Endpoint::with_port`），避免把 0.0.0.0 泄漏进描述符 |

## 正面结论

- **全程未 hack 任何 radiata 内部**：join、组网、资源读写、观测全部通过公共门面（NodeHandle 命令/查询 + PacketConsumer + KeyProvider + StorageFactory 扩展点）完成。唯一的库缺陷（#3）以库修复落地，而非 example 绕过。
- 公共观测面（`GetObservability`/`PageMembers`/`PageSessions`/`GetNodeStatus`）足以支撑外部绞手完成正确性、可用性、拓扑形状验证，无需内部插桩。
- 扩展点（PacketConsumer + 自定义 protocol tag）让数据面健康探针成为一行注册。

## 修复后 E7/E8 复测（全链路修复后）

四层修复全部落地后（per-peer 资源/成员游标 + recovery 遗忘 + 通配绑定）：

- **E8 治愈 12 秒收敛**（修复前：180s 窗口耗尽仍 6:1:2 无归一）；冲突寄存器 9/9 统一到确定性胜者，split-b 9/9 可见（修复前 1/9）。
- E7 分区窗口内 B 侧内部重建仍依赖恢复节奏（退避策略使然，策略性问题而非正确性问题）；正确性不变式——**任何分区期写入在治愈后无操作员干预收敛到单一确定性胜者——成立**。

## 遗留改进建议（按价值）

1. 生产参考 KeyProvider（文件/密钥环）入库或作为独立 crate。
2. join 凭据的"只读查询 + 多次有效"选项，消除串行 join 约束。
3. 恢复控制器对"零会话但持久化描述符非空"的孤立实例触发重连。
4. **反熵游标修复（finding #10，P1）**：同步协议需要每键水位而非名字游标，否则任何“连接空窗期写入 + 名字排序靠前”的资源更新在相关会话上永久丢失——这是集群分裂/网络重挂场景下的数据不一致根源，建议优先设计。
